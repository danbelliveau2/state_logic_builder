# JARVIS Version Log

**JARVIS** is the AI L5X-generation layer of the SDC State Logic Builder:
`src/lib/agentGenerator/` (ir.js, promptBuilder.js, editPlanSchema.js, mergeEngine.js,
validator.js, client.js, generationRules.md) plus the `POST /api/generate` endpoint in `server.js`.

**Architecture (since v1.0.1 — surgical merge):** the model never writes L5X.
It authors a JSON **edit plan** against the selected SDC V4.2 standard template;
the deterministic **merge engine** copies the template verbatim (UTF-8 BOM + CRLF
preserved), applies the plan with exact-match assertions, renames the program and
station display prefix, renumbers rungs, and keeps L5K/Decorated tag data (string
LEN rules included) in sync. Validation = XML/identifier/state checks **plus**
`validateAgainstDiagram` (every diagram action evidenced at its state; no device
commanded in a state whose node has no action for it). Failures at any stage are
fed back to the model, up to `JARVIS_MAX_ATTEMPTS` total calls.

**Model policy:** default `JARVIS_MODEL=claude-opus-5`; `claude-fable-5` is the
quality escalation path for hard stations (worth the price — quality wins);
`claude-sonnet-5` for cheap runs. Every result carries `meta.costEstimate`
computed from real usage tokens (cost is reported for visibility, never
optimized for at the expense of quality; `JARVIS_MAX_COST_USD` default 20 is a
sanity ceiling only).

- Version source of truth: `src/lib/agentGenerator/jarvisVersion.js` (`JARVIS_VERSION` + `HISTORY`)
- Every generated L5X program Description is stamped: `Generated by JARVIS v{version} ({date}) — SDC State Logic Builder`
- The `/api/generate` response includes `meta.jarvisVersion`
- Benchmarks are named by version — see `benchmarks/README.md` and `scripts/jarvisBenchmark.cjs`

Bump the version (and add a row here + a HISTORY entry in jarvisVersion.js) whenever
the pipeline's behavior changes: generation rules edits, template revisions, prompt
structure, validator checks, or repair-loop changes.
